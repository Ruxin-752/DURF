# DURF 项目周报（2026-08-27）

## 本周概况

本周继续改进语言反馈三分类，把 Route1 按原论文链路重新梳理，检查 Route2，并推进能远程体验、匿名收集研究数据的 Web 版。界面会变得更清楚、更像 2D 像素厨房，但原地图布局及锅、菜、灶台、出餐口和出生点均不移动。

## 1. 三分类与准确率

三分类仍只判断 Evaluative（评价）、Imperative（指令）和 Descriptive（描述）。模型现已冻结，避免看过测试结果后继续调参。论文风格代理开发集为 92/99，准确率 92.93%，宏平均 F1 为 92.59%；混合开发集准确率 90.65%；已使用过的论文人工语句代理回归集为 88/96，准确率 91.67%，宏平均 F1 为 88.96%。现有代理数据已达到 87% 目标，但 91.67% 不能写成真实玩家准确率：它不是新的封存盲测，也不是当前玩家自然语言。真实准确率要等 Web 版收集独立真人标注后再报告。界面现在展示三类完整概率，并使用固定的校准参数和拒绝阈值；低置信度输入会明确拒绝。

## 2. Route1 按论文链路解耦

Route1 已统一为：语言 u → 三类反馈 fG → 目标特征 f → 正负情感 ζ → 贝叶斯公式更新权重 w。评价类使用最近轨迹特征，指令类使用被要求动作的特征，描述类使用文本明确提到的特征。原来的五类 classifier 只保留为三类内部的细分路径，不能改写三分类结果。细分类冲突时会记录并回到三分类允许的路径；目标不明确、类别未知或置信度过低时拒绝更新。

## 3. Route2 检查结果

Route2 的代码链路符合当前论文实现：原始语言与已执行轨迹进入十折模型，得到 53 维权重估计，再做独立高斯后验更新并重排候选行为。十个模型及版本绑定、重复事件保护和恢复逻辑均已核对。但一次独立手写自然语言小样本检查仅 1/4 正确；样本太少，不能作为正式准确率，却说明真人表达泛化仍有风险。因此 Web 版会把 Route2 标为实验功能。

## 4. 界面、地图与 Web 数据采集

界面优化重点是避免文字、概率和游戏画面互相遮挡。美术只改变外观和面板，不改原 `.layout` 的格子、墙面、锅、食材、出餐口与出生点；Web 版逐格复制同一布局，并用坐标测试防止误改。Web 研究体验版已经上线，支持知情同意、匿名参与者编号、唯一事件编号、断线队列与批量上传；服务端还增加了短期会话令牌、同源检查、限流以及重复/冲突事件识别。研究表不写入姓名、邮箱或原始 IP，也没有邮件和邀请功能；训练数据导出需要管理员令牌。公开网址：[DURF 暖炉厨房实验室](https://durf-kitchen-lab-study.active-wren-5858.chatgpt.site)。
